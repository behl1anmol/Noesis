# Design decisions (ADRs)

Every design decision in Noesis carries a recorded rationale — the house rule is **"no rationale, no merge."** Decisions live in the devlog's `decisions` table and in the decision log of [`architecture-docs/code-indexer-expanded-architecture.md`](https://github.com/behl1anmol/Noesis/blob/main/architecture-docs/code-indexer-expanded-architecture.md) (Appendix A), which holds the full chosen/reason/alternatives table. This page is the index; ADRs 1–18 belong to the approved baseline documents.

| # | Title | Decision (one line) |
|---|---|---|
| 19 | Reranker sequencing | Build after the M3 evaluation gate; default-on only on a measured NDCG@10 win |
| 20 | Reranker concurrency | Second dedicated single-thread worker, separate from the embedder's |
| 21 | Structural search substrate | Live filesystem via ast-grep-py; the index is bypassed entirely |
| 22 | ast-grep capability exposure | Search only — the rewrite capability is never exposed |
| 23 | Git integration | subprocess git CLI; candidates only shrink the hash set; hash remains truth |
| 24 | Embedder pluggability | Tiny async Protocol encapsulating dim/model_id/prefix; local implementations only |
| 25 | **Hosted embedding: rejected** | No remote embedding of any kind; no HTTP client in `core/`; CI-grep enforced |
| 26 | MCP v2 handling | Scheduled migration checkpoint; FastMCP drives the `mcp` version range until then |
| 27 | Lessons & memories storage | Hybrid: SQLite as system of record + committed rendered `LESSONS.md`; 15-lesson cap |
| 28 | `.gitignore` matching | `pathspec` runtime dep — canonical gitwildmatch, not a hand-rolled matcher |
| 29 | M1 API surface | None — M1 is core-library only; HTTP lands with M2 |
| 30 | Grammar assets | Keep tree-sitter-language-pack 1.12.x + install-time prefetch of all grammars |
| 31 | Generated-lockfile skip-list | Discovery skips committed lockfiles (uv.lock alone was 53% of this repo's chunks) |
| 32 | BM25 TF encoding | `qdrant-client[fastembed]` client-side TF + server-side `Modifier.IDF`; RRF k is server-fixed |
| 33 | Reranker model-loading boundary | New `core/reranker.py`; `sentence_transformers` allowed in exactly two modules |
| 34 | Rerank request-flag default | `rerank` defaults to `reranker.enabled`; disabled reranker returns `reranked:false`, not an error |
| 35 | **M4 gate: reranker default-off** | Quality passed (+0.106 NDCG@10), latency failed (12.2 s p50 on T4) — ships opt-in |
| 36 | `chunk_id` in search hits | Every hit exposes its deterministic point id so `get_chunk` is discoverable |
| 37 | Git fast-path specifics | Anchor validity = `merge-base --is-ancestor`; `-z` parsing; directory entries match as prefixes |
| 38 | Roadmap reorder | Dashboard + watcher promoted to M8; MCP v2 checkpoint renumbered to M9 |
| 39 | M8 runtime deps | jinja2 3.1.6 + watchdog 6.0.0, decision row recorded before install |
| 40 | M8 scope expansion | Per-project watch/auto-reindex (default off), persisted device setting, metadata-only `query_log` |
| 41 | Per-file error capture | Runs continue past per-file failures; `run_file_errors` + `files_failed` surface them |
| 42 | Dashboard registration | Register-only vs register+index split; per-project index config; browse/preview endpoints |
| 43 | Dashboard project deletion | Cancel run → unwatch → delete points by filter → SQLite child-first; source files untouched |
| 44 | Anchored db_path + config lookup | Default DB at `$XDG_DATA_HOME/noesis/noesis.sqlite`; no cwd-relative resolution |
| 45 | Watcher polling fallback | inotify-blind mounts (9p/cifs/nfs/…) get a polling observer, detected via `/proc/mounts` |
| 46 | Polling walk pruning | `PollingObserverVFS` prunes excluded dirs at the walk source (~350 s → ~0.6 s per interval) |
| 47 | Cancellation vs in-flight upsert | `execute_run` shields the in-flight upsert and awaits it on cancel — no orphaned points |
| 48 | Startup orphan-point sweep | Delete points of dead projects at startup; refused when the project table is empty |
| 49 | SQLite↔Qdrant drift self-heal | Count gate per run → per-file scroll → re-embed drifted files + prune orphans |
| 50 | Documentation stack | MkDocs Material on GitHub Pages via Actions: static mkdocstrings (griffe — no runtime deps at docs build), official Pages actions (no gh-pages branch), stdlib-urllib releases generator with a committed empty-state placeholder, dev-only `docs` dependency group |
| 51 | Discovery errors block deletion | A transient walk/stat failure is reported, never silently skipped; file-level errors carry the stored hash forward, a directory-level error suppresses deletion and orphan pruning and blocks the anchor. Extended: a missing *root* is not genuine absence, and an empty scan against non-empty state is refused outright. The two stated exceptions to "never silently skipped" — the `follow_symlinks` cycle-guard `stat` and an unreadable `.gitignore` — were removed by ADR-58; nothing in discovery is logged-but-unrecorded any more. This row also claimed a lost `.gitignore` risks under-ignoring but "cannot cause over-deletion"; that is **retracted**, see ADR-58 |
| 52 | Telemetry writer thread | `record_query` enqueues on a bounded queue and returns; one writer thread owns the connections and is closed at teardown — the usage page becomes eventually consistent. Ownership superseded by ADR-59: the writer is per-`AppContext`, not per process |
| 53 | Drift needs two agreeing reads | The expected total is read on both sides of the Qdrant count; drift is reported only when those readings agree with each other and disagree with the count |
| 54 | Suppression scoped to the unwalked subtree | A directory discovery error blocks deletion and orphan pruning only under its own prefix — project-wide only when no prefix describes what went unseen |
| 55 | Empty-scan escapes | Discovery reports what the walk enumerated before filtering, so a fully filtered tree converges; a genuinely empty root needs an explicit `force`, on REST only — never on the MCP tool an agent calls. The guard covers emptiness that raises nothing, so it defers to a directory error discovery already recorded |
| 56 | Unwalkable-directory ledger and quarantine | Directory-level discovery failures are tracked per project with a consecutive-failure count; after N runs a directory is quarantined and the paths it hides stop being re-queued, so the pending backlog drains. Quarantine bounds the RETRY only — ADR-51/54 keep sole ownership of deletion — and the run that finds the directory walkable again re-hashes its subtree |
| 57 | Automatic promotion to a full walk | A scoped run is promoted to a full one after N scoped runs, once the effective candidate set passes a fraction of the index, or when an unattributable discovery failure leaves the whole index unverified — restoring the drain that only a full run can perform. Amended in the PR #30 review: the working-tree-dirty set counts toward the fraction only while the last **full walk** was clean, since a run reporting any failure leaves that set pinned and promoting cannot shrink it |
| 58 | Screening faults are recorded, non-fatal, and block only what they put in doubt | Faults where the walk saw everything but a *screening input* failed get their own collector lists. `unscreened` (an unreadable or unstattable `.gitignore`) suppresses deletion and orphan pruning under that directory's prefix and blocks the anchor only when it actually held a deletion back; `unidentified` (symlink/cycle-guard `stat`) suppresses nothing, because it can only make the walk over-inclusive. Neither fails the run. Corrects ADR-51: a lost `.gitignore` **can** cause over-deletion — git is last-match-wins, so losing a deeper spec cancels its negation of a shallower exclusion and the file drops out of the walk entirely. Also stops the three calls from raising EACCES/ESTALE out of the whole run, which had been 500-ing structural search. The run's `clean_run` verdict is persisted on a new `index_runs.clean` column instead of being re-derived as `files_failed == 0` — that derivation had already drifted once (ADR-57 round 2) and this adds a term it cannot see |
| 59 | Telemetry writer is per-`AppContext` | The writer's state moves from module globals into a `QueryTelemetry` instance each context owns, which makes `close()` terminal and idempotent for free — a late `record_query` drops its row instead of resurrecting a worker whose DB handle nothing would reap. Deletes all three of the module's carve-outs: the one-live-context invariant, the non-terminal `close()`, and the per-generation queue |
| 60 | Anchor advances past a failure it can name | The git anchor no longer stops for any failure — it stops only for one whose paths cannot be enumerated (an unattributable discovery failure) or for a run that finished `failed`. Everything else the run could not verify — files that failed to index or to hash, paths under an unwalkable subtree, deletions a screening fault held back — is carried in the H1 dirty set, which the next run re-admits as candidates. The guarantee is unchanged (no file whose state is unknown is ever skipped); it is met by recording the doubt rather than by freezing the project, which one unreadable directory — or one unreadable *file* — used to do forever. Subsumes the old rule: on a clean run the carried set is empty and nothing changes. Deletion policy and the `clean` verdict are untouched, and ADR-57's fraction trigger deliberately keeps ignoring the dirty set on a faulted project, because the carried set is a floor promotion cannot get under |
| 61 | Committed lesson files are the durable record | `render-lessons` refuses (exit 1) when the committed files name a lesson the local DB has never seen — it rebuilds a tracked file from a gitignored one, so a stale DB makes it a delete rather than a refresh, and it has destroyed the lesson set once. `lessons import` preserves each lesson's id and reads both files, so the round trip is an identity rather than a renumbering that breaks the cross-references the bodies make to each other. Retired and promoted lessons render to `dev/LESSONS-archive.md`, committed for durability and injected by nothing, because `LESSONS.md` is injected verbatim and a retired lesson there would keep steering sessions. Amends ADR-27 |
| 62 | Qdrant client and server pins are one decision | The server moves to `v1.18.3` and the client gains a `<1.19` ceiling, so both land on 1.18 with zero skew. A default-suite test asserts that zero skew directly — same major *and* minor — rather than the client's own `is_compatible`, which tolerates one minor of drift and so would pass on the very state issue #37 grew out of; `is_compatible` is still checked, to catch a future client that *tightens* its rule. Every other copy of the version — the CI job's image tag, the install guide, the Colab guide's download URL — is pinned to the compose tag by the same test. A `server`-marked tier and a `server-compat` CI job re-check the pair against a live container, because every existing store test uses the embedded client and never performs the version handshake. Correctness only: the golden harness still measures on the embedded client, so this does not establish that retrieval *ranking* survived the jump (#38). **Answered 2026-08-08 under [ADR-66]:** it did not, measurably — dense Recall@10 is identical on both, but hybrid is 0.775 embedded versus 0.713 against a real v1.18.3 server, so the embedded harness over-reports hybrid by 0.062 |
| 63 | Qdrant's own telemetry is disabled in compose | The image ships `telemetry_disabled: false` and reports collection and configuration statistics to `telemetry.qdrant.io` on start. Binding the ports to 127.0.0.1 only governs inbound traffic, so ADR-25's "nothing leaves the machine" was true of our Python and not of the datastore we ship. `QDRANT__TELEMETRY_DISABLED=true` — in compose *and* on the CI service container, which runs the same image and would otherwise ship the same default — asserted by a test |

| 64 | Golden retrieval labels address content, not line numbers | A label is a `path` plus an `anchor` (a substring occurring exactly once in that file), optionally widened by an `anchor_end`; `load_golden` resolves them against the tree being measured and raises when one stops matching. Positional `lines:` ranges are rejected outright. They had rotted: 22 of 46 labels no longer overlapped their own content, and because a result must overlap the range to count, each rotted label silently forced its query to zero — two of them from the day they were written, inside the stored M2 baseline itself. Width follows the question: a `symbol` query's label is its definition site, while `nl`/`structural` labels keep a span, because `dedupe_by_path` keeps only the best-ranked chunk per file and a one-line label would score zero whenever the right region was retrieved but ranked behind another chunk of the same file. `tests/eval/test_golden_labels.py` runs in the DEFAULT suite so rot fails on the commit that causes it, and additionally requires a symbol query's identifier to appear inside its own labeled span — the second route that found the rot, made permanent. **Extended in the PR #42 round-2 review:** the fresh-read check covers `anchor_end` as well as `anchor` (35 of 47 labels had their end unchecked, and the end is the half that drifts), and an anchor unique only by its indentation is now rejected — `nl-09`'s `"        WHERE id = ?"` matched one line while the bare fragment matched 13, so one more SQL statement at that indent would have failed collection. `tests/eval/migrate_labels.py` records the mechanical re-derivation of all 46 |
| 65 | The golden run gates by assertion, in three layers, and never writes a baseline implicitly | Layer 1 asserts same-run relations — M3's exit criterion (hybrid beats dense on Recall@10, especially the symbol subset) and ADR-35's rerank NDCG win — which corpus growth cannot skew because every channel sees the same corpus. Layer 2 compares against one living `baselines/reference.json` and only when its provenance says it is comparable: same models, same store, same questions, corpus within a chunk-count band; otherwise the run fails, never skips, with the tables marked NOT A GATE and the exact re-baseline command. A drop must exceed both a relative band and one query's worth in absolute terms, because a relative band alone silently changes meaning with the score level. Layer 3 makes re-baselining explicit (`NOESIS_EVAL_REBASELINE=1`, refused on a dirty tree); the write-if-missing that made whichever run got there first the standard, and two unconditional writes that dirtied the tree every run, are both deleted. Every run writes a rendered `report_latest.md` — verdicts first, and stamped when the run re-baselined — because the tables were `print`ed and pytest captures stdout, so no invocation without `-s` ever showed them (`-q` is innocent: bare `pytest` hides them too) |
| 66 | The store an eval ran against is part of its provenance | `NOESIS_EVAL_QDRANT_URL` switches the golden corpus fixture from the embedded client to a real Qdrant server on a throwaway collection, and the store kind and server version are recorded in `reference.json` and treated as a hard comparability term, so an embedded-measured reference can never gate a server-measured run. Closes the quality half ADR-62 left open and assigned to #38: sparse IDF is computed server-side and RRF fusion uses a constant the server fixes, so ranking can move between the two implementations with every existing test staying green, because all of them use `QdrantClient(":memory:")` |

| 67 | Golden scoring groups a file's chunks instead of keeping only the best-ranked one | `dedupe_by_path` collapsed each file to its top-ranked chunk before matching, so a file that genuinely contained the answer scored 0 whenever any other chunk of it ranked higher. Measured on the 2026-08-08 run: the query `chunk_point_id` retrieved the chunk holding its definition at rank 2 and scored zero because a *usage* chunk ranked 1; three of forty queries were pinned at zero across all five channels by this alone, so they could never register a regression or an improvement. `group_by_path` keeps the property the collapse existed for — one file occupies one rank slot, so a single file's chunks cannot flood recall — while leaving every retrieved chunk of that file available for matching, and lets one file answer two distinct relevant items through different chunks (structural-03 labels two async methods in embedder.py, structural-08 two endpoints in routes.py; both reach 1.0 on at least one channel of the stored reference, which is only possible if each pair was credited through different chunks). The residual is stated rather than hidden: the cap is per *chunk*, so two same-file labels landing inside one chunk still credit only one and cap that query at `1/len(relevant)`. Lifting it would let a single wide chunk sweep every label in its file — the flooding the collapse existed to prevent — so it is the deliberate boundary, pinned by `test_two_relevant_greedy_credit`. Recall rises, and the metric now measures what the harness documents: whether the relevant code was retrieved, not whether it happened to be the file's top-ranked chunk |
